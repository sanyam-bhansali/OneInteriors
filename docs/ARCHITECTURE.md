# Architecture

## Shape

```
src/
  app/
    page.tsx              landing
    quiz/                 the 9-question brief (client)
    match/                reveal + ranked marketplace (client)
    studios/              roster + [slug] profile (server, static)
    verification/         how we verify
  modules/                domain logic — no React, no ORM
    brief/                types, style vocabulary, persistence
    studio/               types, tiers, delivery-record phrasing
    matching/             scoring engine        ← versioned separately
  components/
    ui/                   design-system primitives
    chrome.tsx            header, footer
  data/
    studios.ts            FIXTURES — replace in Sprint 3
  lib/
    money.ts              integer paise, Indian formatting, bps, splits
prisma/schema.prisma      full data model, not yet wired up
tests/                    money + matching unit tests
```

## The one rule that keeps this clean

**`modules/` never imports from `app/`, and never imports React.**

Domain logic stays renderable-agnostic. That is what lets the same matching
engine run on the server for SEO pages, in the browser during the quiz, and
inside the Capacitor build — without a second implementation to keep in sync.

`app/` may import from `modules/`. A module may import another module only
through its public surface, never by reaching into an internal file.

## Why the modules are drawn where they are

| Module | Owns | Deliberately excludes |
|---|---|---|
| `brief` | The quiz shape, style vocabulary, persistence | Anything about studios |
| `studio` | Studio shape, verification tiers, how a delivery record is phrased | Scoring |
| `matching` | Scoring only. Reads `brief` and `studio`, writes neither | Persistence, UI |

The style vocabulary (`STYLE_TAGS`) lives in `brief` and is imported by both the
quiz picker and portfolio tagging. **If those two ever diverge, matching silently
degrades and nobody notices** — a zero style overlap looks exactly like a
legitimate low score. One list, one place.

## Versioning inside the code

Two things carry their own version, independent of the app's semver, because old
records must never be reinterpreted under new rules:

- `ENGINE_VERSION` in `modules/matching/score.ts` — every stored match keeps the
  version that produced it. Changing weights must never rescore a match a
  customer already saw.
- `policyVersion` on `Consent` in the Prisma schema — under the DPDP Act consent
  is given against a specific policy text. If the text changes, prior consent
  does not carry over.

Bump either deliberately, in its own commit, with the reason in the body.

## Data flow today (v0.1)

```
quiz ──▶ sessionStorage ──▶ /match ──▶ rankStudios(brief, STUDIOS)
                                             │
                                    fixtures in src/data
```

No network, no database, nothing stored server-side. That is why it deploys
with an empty environment.

## Data flow from Sprint 3

```
quiz ──▶ POST /api/brief ──▶ Postgres
                                │
WhatsApp OTP ──▶ session ───────┤
                                ▼
                        rankStudios(brief, studios)
                                ▼
                        Match rows (score + engineVersion frozen)
                                ▼
                 quotation ──▶ contract ──▶ escrow milestones
                                                  │
                                    milestone approvals feed back into
                                    Studio.avgVarianceDays / specComplianceRate
                                                  │
                                          which is Tier 3 (PROVEN)
```

That last loop is the whole business. Everything before the escrow step is a
lead-generation funnel any competitor can clone in a month; the delivery record
generated by money moving through milestones is the part that compounds.

## Deliberate omissions

- **No ML in matching** until >500 completed projects. A customer who cannot
  check the reasoning will not trust the score, and at this stage transparency
  is worth more than accuracy.
- **No 3D/AR.** Modsy raised $73M building exactly that and shut down in 2022.
  It competes for the same engineering months as escrow. Phase 3 at the earliest.
- **No native app codebase.** Capacitor wraps this one.
- **No lead resale, ever.** The moment placement can be bought, the ranking is a
  lie the customer eventually detects, and the honest ranking is the only
  differentiation we have.
